'@operai/meetings-api': patch

Moves meetings-api to zod 4 (4.6.7) and `@hono/zod-openapi` 1.6.3, and `@scalar/hono-api-reference` to 0.12.17, closing the zod memory-exhaustion advisory (GHSA-mrhx-c7xc-m3w5, zod before 4.6.6, no 3.x fix); the Scalar bump is needed because the old one pulled a second, vulnerable zod. Every rejected request keeps its Problem document (422 with `field` and `errors`), but zod's own wording of the messages changes (for example `Required` for a missing member becomes `Invalid input: expected string, received undefined`). A JSON body sent with another Content-Type, or none, now answers 415 instead of 422. A date-time without seconds or with an offset written `+0200` (meeting `startsAt`) is now refused with 422. The OpenAPI document differs only in that the pass-through response and note-document members now state `additionalProperties` (any value), which they always allowed, and in one duplicated `nullable` entry of the speaker-label request body being listed once. Model output and transcription replies are validated by hand-written code, not zod, and behave exactly as before (the injection evals produce byte-identical results). Startup environment checks, exit codes and the refusal of `MEETINGS_AI_PROVIDER=fake` in production are unchanged; only zod's default wording in the startup error text changes. The `/docs` page loads Scalar through a different script.

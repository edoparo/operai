Add letterhead-api (specs/20261116-letterhead-service, ADR 20261116-letterhead-api-is-a-rust-service-with-typst-embedded-for-document-layout-only): the one Rust service in the monorepo, a Cargo workspace (`engine`, a pure crate with Typst embedded for layout only, and `api`, an axum supervisor). It renders a document's pages and PDF from a content model and a versioned letterhead configuration (`POST /v1/render/preview`, `/v1/render/pdf`, `GET /v1/letterheads/status`, called by service clients holding the `letterhead:render` scope), and serves the Letterheads tool: the catalog, the list, versions, history, asset upload, save, restore and a sample-document preview (`/v1/catalog`, `/v1/letterheads/...`), with person auth and entity-scoped permissions (the scope table is shared with crm-api through `docs/fixtures/entity-scope.json`). A letterhead version pins its layout, and old layouts stay compiled in (golden corpus and pdfium conformance in CI). Renders run in a killable worker pool bounded by memory (2 GiB per worker by default), a document over the page limit is refused 422 `too_many_pages`, and nothing of a document is kept (residue test). Assets are sniffed, bounded and, for SVG, rebuilt. Postgres holds the letterheads with immutability triggers and a change record; S3 holds the assets under the EU-residency guard ported from crm-api's `s3Residency.ts`. Wired into the monorepo by hand: a pinned mise `rust` toolchain and a `dev:letterhead` task, a compose service with its database and bucket, a multi-stage non-root Docker image, its Railway declaration, this Changesets shim, the changeset-check path filter, the env-doctor manifest and production template, and a CI workflow that runs fmt, clippy, tests, the golden corpus, the worst-case table, the conformance run and an advisory scan of Cargo.lock.

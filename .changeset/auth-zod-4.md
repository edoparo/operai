Moves auth to zod 4 (4.6.7) and `@hono/zod-openapi` 1.6.3, and `@scalar/hono-api-reference` to 0.12.17, closing the zod memory-exhaustion advisory (GHSA-mrhx-c7xc-m3w5, zod before 4.6.6, no 3.x fix); better-auth already used zod 4, so the service now resolves one zod. Every validation failure keeps its Problem document (type, title, status, detail, instance); only the default wording inside `detail` changes to zod 4's (for example `Required` becomes `Invalid input: expected string, received undefined`). In the OpenAPI document, an enum that is also nullable now lists `null` among its values (six places: the invitation `emailDelivery` in five responses and the `entity` of a user patch); nothing else changes. A JSON body sent with another Content-Type, or none, now answers 415 as a Problem document instead of being read as an empty body; a body that is optional (approving an access request) still accepts no body at all. A malformed `ALLOWED_SIGNUP_DOMAINS` next to another invalid variable now exits with the listed errors instead of a TypeError. A page number above 2^53 and a datetime without seconds are no longer accepted, and the `/docs` page loads Scalar through a different script.

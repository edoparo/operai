Moves crm-api to zod 4 (4.6.7) and `@hono/zod-openapi` 1.6.3, and `@scalar/hono-api-reference` to 0.12.17, closing the zod memory-exhaustion advisory (GHSA-mrhx-c7xc-m3w5, zod before 4.6.6, no 3.x fix); the Scalar bump is needed because the old one pulled a second, vulnerable zod. Every rejected request keeps its Problem document (422 with `field` and `errors`, `answers_invalid` with `path` and `reason`, the NUL refusals with their wording), but zod's own wording of the default messages changes (for example `Required` for a missing member becomes `Invalid input: expected string, received undefined`), a wrong-typed string or array member can list one more error after the first, and when several members are wrong the one named first follows the schema's order. A JSON body sent with another Content-Type, or none, now answers 415 instead of 422. A datetime without seconds or with an offset written `+0200`, a notice id that is not a standard UUID, and an integer beyond the safe range (for example an attachment of more than 2^53 bytes, which used to answer `attachment_too_large`) are now refused with a plain 422. The wizard's decimal quantities and values keep being accepted: zod 4's `.safe()` means integer, so the range is stated outright. The OpenAPI document differs only in that nullable enums now list `null` and the free-form members (`z.record`, `.passthrough()`) state `additionalProperties`, which they always allowed. The `/docs` page loads Scalar through a different script.
